# ТЗ: «Применение рядов и преобразования Фурье для анализа и классификации звуковых сигналов с использованием ИИ»

Рабочее название интерфейса: **«Как ИИ слышит мир»**.

## 1. Что строим

Локальное веб-приложение на Python (Django-монолит). Пользователь записывает или загружает короткий звук, затем проходит пошаговый интерактивный разбор: от исходной волны через ряд Фурье, ДПФ и спектрограмму к ответу нейросети.

Главное требование: **на каждом шаге видно, где и как используется математика**, причём формулы показаны с реальными числами текущей записи, а параметры можно менять.

Проект — творческое задание по математике для студентки 1 курса РГУ нефти и газа им. Губкина. Математика важнее ИИ, строгость максимальная, но всё должно быть объяснимо на защите.

## 2. Стек и ограничения

- Python 3.11+, Django, Django templates. Без отдельного SPA.
- Интерактив: ванильный JS + Plotly.js (графики), KaTeX (формулы). HTMX — по желанию.
- Расчёты: NumPy, SciPy, librosa, soundfile; ffmpeg для декодирования записи из браузера (webm/ogg) в WAV.
- ИИ: PyTorch, transformers, scikit-learn.
- БД почти не нужна: SQLite по умолчанию, записи и результаты лежат во временной папке по ID сессии.
- Запуск локально одной командой, на `localhost` (микрофон в браузере работает без HTTPS). Деплой пока не делаем, но ничего не хардкодим под одну машину.
- Устройство моделей выбирается автоматически: cuda → mps → cpu.
- Все тексты интерфейса на русском.
- Живого стриминга нет: анализ запускается после записи, ползунки пересчитывают результат по уже записанному сигналу.
- Модели загружаются один раз при старте процесса и кэшируются. После первой загрузки приложение должно работать без интернета (все CDN-библиотеки лежат локально в static).

## 3. Вход

- Запись с микрофона 3–5 секунд (MediaRecorder) и загрузка файла WAV/MP3/OGG/WEBM.
- Галерея примеров: голос, свист, хлопок, сирена, музыка, насос норма, насос аномалия. Примеры лежат в `samples/`; они же запасной вариант на защите.
- Нормализация: моно, ресемплинг копии под модель (AST — 16 кГц, CLAP — 48 кГц), обрезка или дополнение тишиной, проверка на тишину и клиппинг.

## 4. Сквозной интерфейс

Одна страница со степпером из 7 шагов. У каждого шага одинаковая структура:

1. график;
2. элементы управления;
3. короткий вывод простыми словами;
4. блок «Где здесь математика» с формулой в KaTeX, подстановкой реальных чисел из записи;
5. раскрывающийся блок «Строго» с определением, теоремой или выводом.

Сверху всегда виден мини-плеер и выбранный участок записи. Кнопка «Показать презентационный режим» увеличивает шрифты и графики для проектора.

## 5. Шаги

### Шаг 1. Звук как функция

- **График:** волна x(t), масштабирование, кнопка прослушивания.
- **Интерактив:** ползунок частоты дискретизации fₛ (например, 2/4/8/16/44,1 кГц) с прослушиванием результата; вариант понижения без антиалиасингового фильтра, чтобы был слышен алиасинг.
- **Математика:** x[n] = f(nΔt), Δt = 1/fₛ. Теорема Котельникова: условие fₛ > 2f_max для сигнала с ограниченным спектром, частота Найквиста fₛ/2.

### Шаг 2. Сборка из гармоник (ряд Фурье)

Пользователь выбирает короткий участок записи длиной T (рекомендуется около 20–50 мс и несколько периодов основного тона, если он есть).

- **График:** сигнал на участке, частичная сумма S_N(t), ошибка, RMSE от N; отдельные гармоники поверх.
- **Интерактив:** N от 1 до 200; переключатель «наша запись / меандр / пила / |x|».
- **Математика:** на периоде T и ω = 2π/T

  f(t) ~ a₀/2 + Σₙ₌₁^∞ (aₙ cos nωt + bₙ sin nωt).

- **Строго:** условия Дирихле; сумма ряда в точке разрыва равна (f(t−0) + f(t+0))/2; для меандра виден эффект Гиббса: выброс около 8,95% от величины скачка не исчезает при N → ∞, а только сужается; равенство Парсеваля и неравенство Бесселя; S_N — наилучшее приближение тригонометрическим многочленом степени N в L².
- **Важно:** запись не обязана быть периодической. Участок периодически продолжается искусственно, и на границах может возникать скачок. Это показать и объяснить.

### Шаг 3. Откуда берётся коэффициент

- **График:** x(t), базисная функция cos(nωt) или sin(nωt), их произведение и закрашенная положительная и отрицательная площадь.
- **Интерактив:** выбор n, синус/косинус; демонстрация ортогональности для пары гармоник n и m.
- **Математика:**

  aₙ = (2/T)∫₀ᵀ f(t) cos(nωt) dt, bₙ = (2/T)∫₀ᵀ f(t) sin(nωt) dt.

  Значение считается численно методом трапеций и рядом показывается аппроксимация через FFT; разница должна быть мала.

- **Строго:** полный вывод: ортогональность системы {1, cos nωt, sin nωt} на периоде и вычисление интегралов через формулы произведения, затем умножение ряда на базисную функцию и почленное интегрирование с указанием условия, при котором оно законно. Комплексная форма: cₙ = (1/T)∫₀ᵀ f(t)e^(−inωt) dt, связь aₙ, bₙ и cₙ.

### Шаг 4. Спектр (ДПФ)

- **График:** |X[k]| от частоты, линейная и дБ-шкала, автоматически подписанные пики.
- **Интерактив:** клик по пику — послушать только эту компоненту; удалить компоненту или полосу и послушать результат обратного ДПФ; НЧ/ВЧ фильтр; окно Rect/Hann.
- **Математика:**

  X[k] = Σₙ₌₀^(N−1) x[n] e^(−2πikn/N), f_k = k·fₛ/N, Δf = fₛ/N.

- **Строго:** переход от cₙ к ДПФ как приближение интеграла суммой (метод прямоугольников) на равномерной сетке; обратное ДПФ; дискретное равенство Парсеваля; алиасинг; утечка спектра и роль окна; сложность O(N²) и O(N log N) у БПФ; симметрия спектра вещественного сигнала. Проверка: собственная наивная реализация ДПФ на маленьком N совпадает с `numpy.fft.fft` с точностью до ошибки округления.

### Шаг 5. Спектрограмма (STFT)

- **График:** тепловая карта, частота от времени; переключатель обычная / мел-шкала; срез выбранного момента как обычный спектр.
- **Интерактив:** длина окна, перекрытие, тип окна, число мел-полос.
- **Математика:**

  X(m, k) = Σₙ x[n] w[n − mH] e^(−2πikn/N), S(m, k) = |X(m, k)|², далее 10·log₁₀(S + ε).

  Мел-шкала: m(f) = 2595·log₁₀(1 + f/700).

- **Строго:** компромисс разрешения по времени и частоте, Δt·Δf ограничено снизу (принцип неопределённости Габора).
- **Вывод:** именно такая картинка попадает на вход модели.

### Шаг 6. Классификация

Три источника ответа, чтобы покрыть как можно больше звуков:

- **Наша дообученная AST** (основная модель): дообучена на классах проекта и реальных записях, раздел 12. Загружается из нашего репозитория Hugging Face с закреплённой ревизией.
- **Исходная AST** (`MIT/ast-finetuned-audioset-10-10-0.4593`): широкая разметка AudioSet, более 500 классов, показываем топ-5. Основные классы перевести на русский, остальные оставить на английском.
- **CLAP** (`laion/clap-htsat-unfused`): zero-shot классификация по текстовым меткам, которые пользователь может дописать сам. Всегда включать метку «другое» и порог уверенности.

Интерактив: добавить шум с заданным SNR, срезать полосу частот или применить изменения из шага 4 и сравнить вероятности до и после.

- **Математика:** softmax: pᵢ = exp(zᵢ/τ) / Σⱼ exp(zⱼ/τ); энтропия как мера неуверенности; для AudioSet учесть, что модель многоклассовая с несколькими метками одновременно: корректно использовать сигмоиду, а не softmax. Показывать то, что реально применяет модель, и не подменять это в объяснении.
- **Строго:** кратко: функция потерь, обучение как градиентный спуск, производные и цепное правило.
- Модель не выдумывать «внутренности»: показать только факт, что на вход идёт лог-мел-спектрограмма из шага 5, разбитая на патчи.

### Шаг 7. Норма или аномалия и обратная связь

- Датасет: `renumics/dcase23-task2-enriched` или `LakoreAI/stgram-mfn-dcase2020-dev` (выбрать по удобству; DCASE 2020 содержит pump). Брать небольшой поднабор, а не весь архив.
- Базовый подход: посчитать AST-эмбеддинги нормальных записей одного типа машины, обучить Local Outlier Factor и получить оценку аномальности.
- Основной подход: модель в духе DCASE обучается только на нормальных звуках определять ID машины, а аномальность считается по её неуверенности. Детали в разделе 12.
- В приложении используется подход, который лучше по AUC на отложенной выборке; LOF остаётся базовым сравнением в отчёте.
- Обучение идёт отдельными скриптами, результат сохраняется в `artifacts/` и публикуется на Hugging Face.
- **Интерактив:** ползунок порога, матрица ошибок, ROC-кривая и AUC на тестовой выборке.
- **Математика:** расстояния в пространстве эмбеддингов, идея LOF как сравнения локальной плотности, TPR/FPR, AUC.
- **Ограничение:** детектор применяется только к записям машин того же типа из датасета или к примерам из галереи. Для произвольных звуков с микрофона выводить предупреждение, что результат неприменим: нет эталона нормальной работы именно этой машины.

Обратная связь формируется по правилам на основе рассчитанных чисел, а не свободным текстом:

- звук определён: главный класс, уверенность и описание спектра с реальными частотами;
- тональный сигнал или широкополосный шум: определяется по пикам и спектральной плоскости;
- модель не уверена: предложить записать ближе к источнику;
- плохая запись: тишина, клиппинг или низкий SNR;
- аномалия: отличие от нормальных образцов и рекомендация проверки, без заявления о конкретной поломке.

Никогда не говорить о реальной диагностике оборудования как о надёжной: это учебная демонстрация.

## 7. Тесты математики

- Синус частоты f даёт пик ДПФ на f и правильную амплитуду.
- Сумма двух синусов даёт два пика.
- Обратное ДПФ восстанавливает сигнал.
- Парсеваль выполняется для случайного сигнала.
- Наивное ДПФ совпадает с `numpy.fft.fft`.
- Коэффициенты меандра сходятся к аналитическим: bₙ = 4/(πn) для нечётных n, остальные равны 0.
- Для меандра виден выброс около 9% от скачка.
- Ошибка S_N не растёт с ростом N на гладком сигнале.

## 12. Обучение моделей

Обучаем на RTX 2060 Super (8 ГБ). Mac M4 используем для разработки и инференса. С нуля на AudioSet не обучаем; качество получаем дообучением и своими данными.

### 12.1. Классификатор звуков

**Данные:**

- ESC-50 (50 классов, 2000 клипов) с готовыми 5 фолдами;
- UrbanSound8K как опция с готовыми 10 фолдами;
- свои записи с микрофона защиты для классов проекта: голос, свист, хлопок и другие;
- метка «другое» или порог уверенности для незнакомых звуков.

**Правила разбиения:** клипы одного исходного файла и одной записи не попадают одновременно в train и test. Свои записи делятся по сессиям, а финальный тест не используется для настройки.

**Обучение AST:**

1. Заменить выходной слой под классы проекта.
2. Обучить только новый слой.
3. Разморозить всю модель с низким learning rate и warmup.
4. Mixed precision, маленький батч и gradient accumulation.
5. Early stopping и сохранение лучшего чекпойнта по валидации.

Аугментации: шум с разным SNR, сдвиг по времени, SpecAugment, mixup. Если память всё равно заканчивается, использовать облачный GPU на время обучения.

**Эксперимент для отчёта.** На одних и тех же фолдах сравнить:

1. маленькую CNN на исходной волне;
2. CNN такого же порядка сложности на лог-мел-спектрограмме;
3. дообученную AST.

Метрики: accuracy, macro-F1, матрица ошибок, среднее и стандартное отклонение по фолдам, качество при разных SNR и на своих записях. Результат не подгонять: если спектрограмма не выиграет, описать это в выводах.

### 12.2. Норма и аномалия

- Основной тип машины: pump; при наличии времени добавить другие типы.
- Обучение только на нормальных записях: классификация ID машины на лог-мел-спектрограммах или STgram-подобных признаках.
- Оценка аномальности: отрицательная лог-вероятность истинного ID машины.
- Метрики: AUC и pAUC по каждому ID, порог выбирается только на отдельной валидации.
- Сравнение с базовым LOF на AST-эмбеддингах и с автоэнкодером, если останется время.

### 12.3. Трекинг

Логировать конфиг, seed, commit, версии данных и кривые обучения в MLflow или TensorBoard. Метрики и графики сохранять в `artifacts/` для отчёта.
