# Обучение моделей: что, на чём и как (для работы с Codex)

Документ для параллельной работы: вы с Codex обучаете модели в `training/`, я тем временем делаю приложение
(`analyzer/`). Готовые артефакты я подключу на этапах 4–5 и 8, поэтому важно соблюсти **контракт выхода** (раздел 7).
Основание — SPEC.md §12. Ниже везде «проверить» означает: я не уверен, Codex должен проверить и записать результат.

## 0. Правила (дайте их Codex первым сообщением)

1. Работать только в `training/`, `artifacts/`, `data/`, `runs/`. Не трогать `analyzer/`, `config/`, `tests/`.
2. **В git не добавлять:** данные (`data/`), веса (`*.safetensors`, `*.pt`, `*.bin`), `runs/`, `artifacts/*`, `.env`, токены.
   `.gitignore` это уже исключает — не ослаблять его.
3. **Ничего не публиковать на Hugging Face** и не логиниться. Публикация — отдельный этап после проверки лицензий.
4. **Тестовые данные не использовать ни для чего, кроме финальной оценки:** ни для early stopping, ни для выбора
   гиперпараметров, ни для порога. Если результат плохой — так и записать, не перебирать настройки на тесте.
5. Каждый запуск: фиксированный seed, конфиг YAML из `training/configs/`, в `artifacts/<run>/` сохранить
   `config.yaml`, `git_commit.txt`, `env.txt` (`pip freeze` / `uv pip freeze`), `data_manifest.json`
   (список файлов + sha256 списка), `metrics.json`, кривые в TensorBoard (`runs/<run>/`).
6. Перед долгим запуском (> 30 мин): прогнать 50 шагов, измерить скорость, пересчитать оценку времени и показать
   её вместе с конфигом. Не скачивать больше 5 ГБ без отдельного подтверждения.
7. Окружение уже готово: `uv sync --extra ml`, запуск `uv run python training/<скрипт>.py --config training/configs/<x>.yaml`.
   GPU: RTX 2060 Super 8 ГБ, torch 2.15 + CUDA 13.2, transformers 5.22. Устройство выбирать cuda → mps → cpu.

## 3. Задача A: сравнение волна-CNN / мел-CNN / AST на ESC-50

**Разбиение.** Готовые фолды ESC-50 (клипы одного исходника уже в одном фолде). Для теста фолда k:
validation = фолд (k mod 5) + 1, train = остальные три. Тестовый фолд — только для финальной метрики.

**Общее для всех трёх:** моно 16 кГц, длина 5 с, seed 2026 (и ещё 2 seed для разброса, если хватит времени),
одинаковый бюджет эпох и одинаковые аугментации волны: сдвиг по времени (циклический, до ±0,5 с), гауссов шум
со случайным SNR 10–30 дБ, mixup α = 0,2. SpecAugment — только для мел-моделей (это часть преимущества
представления, честно описать в отчёте). Оптимизатор AdamW, cosine schedule с warmup, early stopping
по macro-F1 на validation, сохранять лучший чекпойнт.

**Модели (сложность одного порядка для двух CNN):**
1. **Волна-CNN** — 1D, в духе M5/M11: первая свёртка с широким ядром (80, шаг 4), затем 4–6 блоков conv-BN-ReLU-pool,
   global average pooling, линейный слой. Цель — около 0,5 М параметров.
2. **Мел-CNN** — 2D, 4 блока conv-BN-ReLU-pool, GAP, линейный слой, тоже около 0,5 М параметров.
   Вход: лог-мел 64 или 128 полос, n_fft 1024, hop 160 (10 мс), окно Ханна.
   Записать точное число параметров обеих CNN в `metrics.json`.
3. **AST** — `MIT/ast-finetuned-audioset-10-10-0.4593` с закреплённой revision `f826b80d28226b62986cc218e5cec390b1096902`.
   - Заменить классификатор на 50 классов (`num_labels=50`, `ignore_mismatched_sizes=True`), `problem_type="single_label_classification"`.
   - Фаза 1: заморозить всё, кроме головы, 3–5 эпох, lr 1e-3.
   - Фаза 2: разморозить всё, lr 1e-5…3e-5, warmup 10% шагов, 15–25 эпох.
   - fp16 (`torch.autocast`), батч 4–8, gradient accumulation до эффективного 16–32, при нехватке памяти — gradient checkpointing.
   - **Ускорение (рекомендую):** клипы ESC-50 по 5 с, а AST по умолчанию берёт 1024 кадра (10,24 с) — половина вычислений
     уходит на паддинг. Можно взять `max_length=512` в конфиге и препроцессоре и обрезать позиционные эмбеддинги по времени
     (так делали авторы AST для ESC-50). Позиции хранятся как сетка 12 × 101 по (частота, время): оставить первые 12 × 51.
     Проверить, что сохранённая модель грузится через `from_pretrained` без предупреждений о несовпадении размеров.
   - **Признаки — только через `ASTFeatureExtractor`** из той же revision. Не писать свою мел-спектрограмму для AST.

**Метрики (в `artifacts/report_esc50/`):**
- по каждому фолду и каждой модели: accuracy, macro-F1, матрица ошибок (`.json` + `.png`);
- сводка: среднее ± стандартное отклонение по 5 фолдам (`summary.csv`);
- устойчивость к шуму: тестовый фолд с белым шумом при SNR = 20, 10, 5, 0 дБ (шум фиксированного seed), те же метрики;
- время обучения и инференса на клип.

Если мел-CNN не выиграет у волна-CNN или AST не выиграет у мел-CNN — так и записать. Подгонять нельзя.

## 4. Задача C: детектор аномалий насоса

**Данные.** DCASE 2020 Task 2 dev, pump: 16 кГц, клипы 10 с, ID 00, 02, 04, 06.
- `train/` (только норма) → разбить по файлам на train/val 90/10 со стратификацией по ID, seed 2026;
- `test/` (норма и аномалия) — **только финальная оценка**.

**Признаки (один модуль `training/common/features.py`, его же импортирует приложение):**
лог-мел, 16 кГц, n_fft 1024, win 1024, hop 512, Ханн, 128 мел-полос, `power=2`, `10·log10(S + 1e-10)`.
Все параметры записать в `artifacts/anomaly_pump/feature_config.json`. Приложение будет считать признаки ровно по ним.

**Основной подход (SPEC §12.2):** классификатор ID машины, обучение только на норме.
- Архитектура: небольшая 2D-CNN или ResNet / MobileFaceNet-подобная на лог-мел (STgram-MFN — по желанию).
- Обучение на случайных вырезках по 64 кадра (≈ 2 с). Инференс — усреднение по скользящим вырезкам клипа.
- Потеря: кросс-энтропия (ArcFace — опционально, отдельным экспериментом).
- **Оценка аномальности клипа:** `score = −log p(истинный ID | клип)`, усреднённая по вырезкам.
- Early stopping — по точности ID на val (это нормальные данные, утечки нет).
- **Порог** — только по val: 90-й перцентиль score нормальных клипов val для каждого ID. Записать, как выбран.

**Бейзлайн LOF:**
- эмбеддинги исходной AST (та же revision): среднее `last_hidden_state` по токенам, 768 чисел на клип;
- `LocalOutlierFactor(novelty=True, n_neighbors=20)` на нормальных train-эмбеддингах каждого ID;
- `n_neighbors` зафиксировать заранее: подбирать его на тесте нельзя, а аномалий в val нет;
- score = `−score_samples`.

Автоэнкодер — только если останется время.

**Метрики (в `artifacts/anomaly_pump/`):** AUC и pAUC (FPR ≤ 0,1) по каждому ID и среднее, для обоих подходов;
ROC-точки (`fpr`, `tpr`, `thresholds`) в JSON для графика в приложении; матрица ошибок при выбранном пороге;
`test_scores.csv` (файл, ID, метка, score). В приложение пойдёт подход с лучшим средним AUC (SPEC §5, шаг 7).
Ориентир: официальный бейзлайн-автоэнкодер DCASE 2020 давал на pump AUC порядка 0,7 — уточнить по технической статье
задачи и не выдавать за наш результат.

## 5. Задача B: классификатор классов проекта (модель для приложения)

**Классы** (имена в `config.json` — английские, русские подписи — в `labels_ru.json`):

| id | label | рус. | Источники |
|---|---|---|---|
| 0 | speech | голос | FSD50K Speech, свои записи |
| 1 | whistling | свист | FSD50K Whistling, **свои записи (обязательно)** |
| 2 | clapping | хлопки | FSD50K Clapping, свои записи |
| 3 | siren | сирена | FSD50K Siren |
| 4 | music | музыка | FSD50K Music |
| 5 | knock | стук | FSD50K Knock |
| 6 | cough | кашель | FSD50K Cough |
| 7 | dog | собака | FSD50K Dog / Bark |
| 8 | footsteps | шаги | FSD50K Walk, footsteps |
| 9 | other | другое | случайные клипы прочих классов FSD50K |

Набор можно менять, но тогда обновить таблицу и `labels_ru.json`. Брать клипы FSD50K, где есть ровно один из
наших классов (по иерархии AudioSet), длина ≤ 10 с, лицензия CC0 / CC BY (если выбран открытый вариант из раздела 2).
Сбалансировать: не больше ~300 клипов на класс.

**Свои записи** (`data/own/<session>/<class>/*.wav`):
- минимум 5 сессий — разные дни, комнаты, люди, телефон/ноутбук; в каждой по 10–20 клипов на класс, 3–5 с;
- сессии 1–3 → train, 4 → val, 5 (лучше записать в аудитории защиты) → **финальный тест, не открывать до конца**;
- клипы одной сессии никогда не делятся между частями;
- записать `data/own/sessions.csv`: сессия, дата, место, устройство, кто записывал (без ФИО посторонних).

**Разбиение FSD50K:** официальные dev/eval; train/val — внутри dev, группируя по автору (uploader), если поле есть.

**Обучение:** как AST в задаче A (две фазы, fp16, early stopping по macro-F1 на val), `max_length=1024`
(в приложении клипы до 10 с), аугментации: шум SNR 5–30 дБ, сдвиг, SpecAugment, mixup.
Запрет утечки: ни одного Freesound ID одновременно в train и test.

**«Другое» и неуверенность:** класс `other` плюс порог по максимальной вероятности. Порог выбрать на val
(например, при котором 95% правильных ответов val остаются уверенными) и записать в `threshold.json`.

**Метрики:** accuracy, macro-F1, матрица ошибок на тесте FSD50K и **отдельно** на своей финальной сессии,
устойчивость при SNR 20/10/5/0 дБ.
